# Аудит кода FLAKS — найденные проблемы и исправления

Дата проверки: 2026-07-05.
Проверены: `api/order.js`, `app.js`, `assets/cart.js`, `assets/motion.js`, `assets/seo-lang-switch.js`, `vercel.json`, `.vercelignore`, `serve.ps1`, `index.html`, `cart.html`, `contacts.html`, `404.html`, шаблон страницы товара, `data.js`.

Обозначения серьёзности: 🔴 критично · 🟠 важно · 🟡 средне · ⚪ мелочь / формулировки.

## 1. БЕЗОПАСНОСТЬ

### 1.1 🔴 `api/order.js` — сервер полностью доверяет ценам и остаткам из браузера

**Где:** `api/order.js:27–54`.

Поля `price`, `stock`, `requestQty` берутся из тела запроса как есть. Проверки
`requestQty <= stock` и `total >= 2000` выполняются по данным, которые прислал сам клиент,
то есть защиты не дают вообще: любой может отправить заявку с ценой 1 грн и «остатком» 99999,
и менеджер получит письмо с ложными ценами и суммами.

**Исправление:** пометить суммы в письме как неподтверждённые и/или сверять цену по SKU на сервере.
Минимальный вариант — добавить в `orderText()` предупреждение и ограничить значения:

```js
// в validateOrder(), после normalizedItems:
const MAX_ITEMS = 100;
const MAX_QTY = 10000;
const MAX_PRICE = 10_000_000;
if (items.length > MAX_ITEMS) {
  return { ok: false, status: 400, message: "Too many items" };
}
// в map():
price: Math.min(toNumber(item.price), MAX_PRICE),
requestQty: Math.min(Math.max(1, Math.floor(toNumber(item.requestQty))), MAX_QTY),
```

```js
// в orderText(), после строки с товарами:
lines.push("", isRu
  ? "Внимание: цены и остатки указаны клиентом и требуют проверки по прайсу."
  : "Увага: ціни та залишки вказані клієнтом і потребують перевірки за прайсом.");
```

Полный вариант — на сервере загрузить каталог (тот же JSON, что в `data.js`) и подставлять
цену/остаток по `sku`, игнорируя присланные клиентом значения.

### 1.2 🔴 `api/order.js` — нет защиты от спама и перебора (rate limiting)

**Где:** `api/order.js:173` (весь handler).

Эндпоинт `/api/order` открыт без ограничений: скрипт может слать тысячи заявок,
забивая почту и Telegram владельца и сжигая квоту Resend (а на платном тарифе — деньги).

**Исправление (минимум, без внешних сервисов):** honeypot-поле + ограничение размера.

```js
// в handler(), до validateOrder:
const bodyForCheck = typeof request.body === "string" ? request.body : JSON.stringify(request.body || {});
if (bodyForCheck.length > 100_000) {
  response.status(413).json({ error: "Payload too large" });
  return;
}
// honeypot: скрытое поле "website" в форме; боты его заполняют
if (request.body && request.body.website) {
  response.status(200).json({ ok: true }); // тихо принимаем и выбрасываем
  return;
}
```

```html
<!-- в checkoutFormHtml() в assets/cart.js добавить скрытое поле: -->
<input name="website" tabindex="-1" autocomplete="off"
       style="position:absolute;left:-9999px" aria-hidden="true">
```

и передавать его в payload: `website: formData.get("website")?.toString() || ""`.

**Исправление (полноценное):** лимит по IP через Vercel KV / Upstash Ratelimit
(например, 5 заявок за 10 минут с одного IP).

### 1.3 🟠 `api/order.js:43` — падение с 500 вместо 400 при `null`-теле

`JSON.parse("null")` или тело-массив проходят парсинг, затем `body.items` /
`body.customer?.name` бросают TypeError → клиент получает 500 «Order delivery failed»
вместо честного 400.

```js
// в validateOrder(), после блока JSON.parse:
if (!body || typeof body !== "object" || Array.isArray(body)) {
  return { ok: false, status: 400, message: "Invalid JSON" };
}
```

### 1.4 🟠 Внутренние файлы публично доступны на проде

**Где:** `.vercelignore`.

В деплой попадают и скачиваются любым желающим:
- `refresh-data-ua.mjs` (34 КБ внутренней логики), `seo-spec.mjs`, `seo-spec.test.mjs`, `build-merchant-images.py`;
- `.env.example` (раскрывает, какие переменные окружения используются: RESEND, TELEGRAM);
- `data.js` — 7,3 МБ, **нигде не подключается** (все страницы грузят `data.8a4bc904d121.js`) — мёртвый дубликат;
- `flaks-screenshot-updated.png` — не попадает под маску `flaks-*-screenshot.png` (маска требует `-screenshot` в конце имени).

**Исправление — дополнить `.vercelignore`:**

```
refresh-data-ua.mjs
seo-spec.mjs
seo-spec.test.mjs
build-merchant-images.py
.env.example
data.js
flaks-screenshot-updated.png
*.png
!assets/**
```

(последние две строки — либо просто перечислить png из корня; `assets/` трогать нельзя).
Файл `data.js` можно вообще удалить из репозитория — он не используется.

### 1.5 🟡 CSP допускает `'unsafe-inline'` для скриптов

**Где:** `vercel.json:22`.

`script-src 'self' 'unsafe-inline'` почти обнуляет защиту CSP от XSS: любой внедрённый
инлайн-скрипт выполнится. Сейчас инлайн-скрипты нужны (GA-загрузчик, ленивый каталог,
JSON-LD не требует разрешения). Правильное решение — вынести два инлайн-скрипта
`index.html` в файлы (`assets/ga-loader.js`, `assets/catalog-loader.js`), убрать
`'unsafe-inline'` из `script-src` и добавить `https://www.googletagmanager.com` в
`connect-src` при необходимости. На сгенерированных страницах GA-сниппет тоже инлайновый —
его надо заменить тем же `assets/ga-loader.js` в генераторе (`build-seo.mjs`).

### 1.6 ⚪ `api/order.js:135` — `reply_to` из данных клиента

Email клиента без валидации формата попадает в `reply_to`. Resend отклонит явный мусор,
но лучше проверить формат:

```js
const email = cleanText(body.customer?.email, 140);
const safeEmail = /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email) ? email : "";
```

## 2. БАГИ (функциональность)

### 2.1 🔴 `assets/cart.js` — поле «Количество» теряет фокус после каждой цифры

**Где:** `cart.js:434–440` (обработчик `input`) + `cart.js:449` (`flaks-cart-change` → `renderAll`).

Каждое нажатие клавиши в поле количества вызывает `updateQty` → `writeCart` → событие
`flaks-cart-change` → `renderAll()` → `innerHTML` корзины пересоздаётся → **поле ввода
уничтожается и фокус пропадает**. Ввести «25» обычным способом нельзя: после «2» набор
прерывается. Это ломает основной сценарий оформления заявки.

**Исправление:** сохранять на событии `change` (когда пользователь закончил ввод),
а на `input` только ограничивать максимум:

```js
// заменить блок document.addEventListener("input", ...) на:
document.addEventListener("input", (event) => {
  const input = event.target.closest("[data-cart-qty]");
  if (!input) return;
  const max = toNumber(input.getAttribute("max"));
  if (max > 0 && toNumber(input.value) > max) input.value = String(max);
});

document.addEventListener("change", (event) => {
  const input = event.target.closest("[data-cart-qty]");
  if (!input) return;
  updateQty(input.dataset.cartQty, input.value);
});
```

### 2.2 🟠 `vercel.json` — правило `/data(.*).js` перебивает кэш для `/data.js`

**Где:** `vercel.json:36–52`.

Шаблон `/data(.*).js` матчит и сам `/data.js` (группа `(.*)` может быть пустой), а в Vercel
при совпадении нескольких правил приоритет у более позднего. В итоге задуманный
`max-age=0, must-revalidate` для `/data.js` перекрывается `immutable, max-age=31536000` —
если когда-нибудь вернуться к нехэшированному `data.js`, браузеры будут год держать
устаревший каталог.

**Исправление:** ужесточить шаблон хэшированных файлов:

```json
{
  "source": "/data.([a-f0-9]+).js",
  "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }]
}
```

### 2.3 🟠 `vercel.json:27–34` — `immutable` на год для нехэшированных скриптов

`/assets/(.*)` получает `max-age=31536000, immutable`, но `assets/cart.js`,
`assets/motion.js`, `assets/seo-lang-switch.js` **не имеют хэша в имени**. Любая правка
корзины (включая фиксы из этого отчёта) не дойдёт до вернувшихся посетителей до года —
они будут выполнять старый JS.

**Исправление:** отдельное правило для JS в assets ПОСЛЕ общего (позднее правило побеждает):

```json
{
  "source": "/assets/(.*)",
  "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }]
},
{
  "source": "/assets/(.*).js",
  "headers": [{ "key": "Cache-Control", "value": "public, max-age=3600, must-revalidate" }]
}
```

Либо перевести эти три файла на хэшированные имена, как сделано с `data.*.js`.

### 2.4 🟠 `app.js:351–354` — ссылки на страницы товара без URL-кодирования

```js
return `products/${product.sku.toLowerCase()}.html${suffix}`;
```

Если SKU содержит пробел, `/`, `#`, `?` или кириллицу, ссылка ломается или ведёт не туда.
Сейчас SKU вида `FLK-00001` безопасны, но при появлении «сырых» артикулов ссылки молча
сломаются.

```js
return `products/${encodeURIComponent(product.sku.toLowerCase())}.html${suffix}`;
```

### 2.5 🟡 `assets/cart.js:388` — сообщение об ошибке сервера теряется

`if (!response.ok) throw new Error("Order failed")` — конкретная причина
(«Requested quantity exceeds stock», «Minimum order total…») выбрасывается, пользователь
всегда видит общее «Не удалось отправить заявку».

```js
if (!response.ok) {
  let message = "";
  try { message = (await response.json()).error || ""; } catch {}
  throw new Error(message || "Order failed");
}
// и в catch:
} catch (error) {
  status.textContent = error && error.message && error.message !== "Order failed"
    ? `${t("failed")} (${error.message})`
    : t("failed");
  form.querySelector("button[type='submit']").disabled = false;
}
```

### 2.6 🟡 `index.html:280` — заголовок колонки не совпадает с переводом

В HTML зашито `<th data-i18n="tableAction">Заявка</th>`, а в `app.js` перевод
`tableAction: "Кошик" / "Корзина"`. До ленивой загрузки `app.js` виден один текст, после —
другой. Заменить статический текст на «Кошик».

### 2.7 🟡 `serve.ps1` — локальный сервер отдаёт 404 для `/articles`

На проде Vercel отдаёт `articles/index.html` для `/articles`, локальный dev-сервер — нет
(проверяет только `[IO.File]::Exists`). Локальное тестирование навигации расходится с продом.

```powershell
# после вычисления $fullPath:
if ([IO.Directory]::Exists($fullPath)) {
  $fullPath = [IO.Path]::Combine($fullPath, "index.html")
}
```

### 2.8 🟡 `app.js:196–198` — непоследовательное форматирование количества

`formatQty` для целых чисел возвращает `String(qty)` без разделителей тысяч, а для дробных —
с локалью. «12037 шт.» и «1 037,5 шт.» в одной таблице. Единообразно:

```js
function formatQty(qty) {
  return qty.toLocaleString("uk-UA");
}
```

### 2.9 ⚪ `assets/cart.js:79` — валюта всегда в формате `uk-UA`

`money` создаётся один раз с локалью `uk-UA`, даже когда интерфейс на русском. Для гривны
разница минимальна («2 000,00 грн»), но для последовательности можно форматировать по
`lang()` в момент вывода.

### 2.10 ⚪ `api/order.js:86` — бессмысленный тернарник

`${isRu ? "Дата" : "Дата"}` — обе ветки одинаковы. Заменить на `Дата`.

### 2.11 ⚪ Дублирование констант

`MIN_ORDER_TOTAL = 2000`, телефон и email продублированы в `api/order.js`, `assets/cart.js`,
`data.js (store)` и десятке HTML-страниц. При смене телефона/почты/минималки легко забыть
одно из мест (телефон уже расходился в истории коммитов). Минимум — вынести контакты
в `data.store` и брать оттуда в `cart.js`.

## 3. НЕТОЧНЫЕ ФОРМУЛИРОВКИ / КОНТЕНТ

### 3.1 🟡 `index.html:15–18` — og:description на русском при украинской странице

`<meta property="og:description">` содержит русский текст («Каталог металлообрабатывающего
инструмента…»), при этом `<html lang="uk">`, title и description — украинские. В превью
соцсетей/мессенджеров украинская страница показывается с русским описанием. Заменить на:

```html
<meta property="og:description"
  content="Каталог металообробного інструменту FLAKS: ціни в гривні без ПДВ, наявність, заявки по email і телефону." />
```

### 3.2 🟡 `contacts.html:77` — «FLAKS contacts» по-английски

Айбров (eyebrow) на странице контактов — единственная английская строка на укр/рус сайте.
Заменить на языковые спаны, как везде:

```html
<p class="eyebrow"><span data-lang-content="uk">Контакти FLAKS</span><span data-lang-content="ru" hidden>Контакты FLAKS</span></p>
```

### 3.3 ⚪ `contacts.html:39` — JSON-LD: город латиницей при адресе кириллицей

`"streetAddress": "вул. Георгія Тарасенка, 18"` + `"addressLocality": "Kharkiv"` —
смешение языков в одном адресе. Для консистентности: `"addressLocality": "Харків"`
(или весь адрес латиницей, как в Merchant Center — но одинаково).

### 3.4 ⚪ `cart.html:53–54` — дефис вместо тире

«Мінімальна сума замовлення - 2 000 грн» → «Мінімальна сума замовлення — 2 000 грн»
(в обеих языковых версиях).

### 3.5 ⚪ Почта Gmail как официальный контакт

Везде указан `tpolegat@gmail.com`, при этом `.env.example` предполагает
`orders@flaks.com.ua`. Для доверия покупателей и для доставляемости писем Resend
(дефолтный отправитель `onboarding@resend.dev` часто уходит в спам) стоит настроить
почту на домене flaks.com.ua и проставить её единообразно: `RESEND_FROM`, JSON-LD,
шапки/подвалы всех страниц.

### 3.6 ⚪ SEO: RU-версия невидима для поисковиков

Перевод выполняется только JS (`?lang=ru` + `data-lang-content`), тегов
`<link rel="alternate" hreflang="ru-UA" ...>` нет. Google индексирует только украинскую
версию; для RU-запросов страницы не ранжируются. Если RU-трафик важен — нужны либо
hreflang с отдельными URL (`?lang=ru`), либо отдельные RU-страницы в генераторе.

## 4. ПРОЧЕЕ (гигиена репозитория и мелочи)

- 🟡 **GA подключён по-разному:** `index.html`/`cart.html` грузят gtag лениво по первому
  взаимодействию, а `contacts.html`, `404.html` и все страницы товаров — синхронно в `<head>`
  (замедляет LCP тысяч страниц товаров). Стоит унифицировать на ленивый вариант в генераторе.
- ⚪ В корне репозитория лежат пустые `server.err.log`, `server.out.log` и 4 скриншота
  (~390 КБ) — удалить и добавить в `.gitignore` (`*.log` там, вероятно, уже есть — проверить,
  что файлы не закоммичены заново).
- ⚪ `data.js` (7,3 МБ) — неиспользуемый дубликат `data.8a4bc904d121.js`: удалить, генерацию
  оставить только для хэшированного имени.
- ⚪ `assets/cart.js:210` — кнопка закрытия корзины: `aria-label="Close"` по-английски и
  символ «x» вместо «×». Мелочь для доступности: `aria-label` локализовать через `t()`.

## Что в порядке (проверено, проблем нет)

- XSS: `escapeHtml` последовательно применяется во всех местах вставки HTML
  (`app.js`, `cart.js`), включая данные из `localStorage` и письма (`orderHtml`).
- Path traversal в `serve.ps1` закрыт (`GetFullPath` + проверка префикса корня).
- Секретов в репозитории нет: `.env.example` пустой по ключам, токены только в env Vercel.
- `Promise.allSettled` в handler корректно считает доставку успешной, если сработал
  хотя бы один канал (email или Telegram).
- Заголовки безопасности (`X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors`,
  `form-action`) настроены разумно.
